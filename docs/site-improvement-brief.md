## Shared architectural decisions
1. Stay on static Astro, existing YAML metadata, and existing canonical URLs/PDF paths. No database, new framework, analytics, external fonts, external services, or new tracking. Do not generalize the archive schema in this tranche; document the hardcoded Amnesty loader/template as a future gap.
2. Primary editorial layout: open stacked collection/document entries, consistent reading width and spacing, modest responsive headings, semantic sections, clear text labels for evidence type and publisher/archive status. Remove rather than disguise content cards. A single-rule warning is allowed, an enclosed warning card is not.
3. Reader wayfinding: breadcrumb links on collection/document pages; compact inline 'On this page' links to meaningful section IDs; relevant anchors scroll clear of header. Expose document titles/links sooner on the homepage and collection page without duplicating giant blocks or pretending this is a large catalogue. On collection pages keep withdrawal/publisher context ahead of the document list, then timeline/editorial/source material. Do not place raw download links ahead of the withdrawal notice.
4. Record tools: accessible progressively enhanced Copy citation and Copy SHA-256 buttons on document pages; human-readable selectable citation/checksum remains usable without JS and when clipboard access fails. Citation uses document title, publisher, known publication date (without fabricating day precision), archive record canonical URL, and explicitly says preserved copy of a withdrawn report where the metadata supports it. Do not conflate archive-obtained, publication, and last-reviewed dates. Shared print CSS prints readable records, provenance, URLs, and checksums while omitting navigation/action chrome; no clipped metadata.
5. Test hardening: extend content verification to compare hosted local PDF file sizes and SHA-256 bytes with metadata and fail clearly on missing/mismatched files and unsafe local paths. No network-dependent mandatory tests. Add node:test fixture-based negative/positive coverage; do not mutate real PDFs for tests. Keep existing schema verification. Never silently rewrite hashes/metadata to make a failing check pass.
6. Accessibility: keyboard operation and visible focus, semantic headings and landmarks, underlined prose links, long title/URL/hash wrapping, 320/375px mobile and desktop, 200% zoom, sufficient contrast and reasonable target sizes. All reading/navigation/download access works without client JS.
7. Full-site modern design: cohesive type/space/colour tokens, deliberate editorial hierarchy and responsive grid alignment (not card grids), clean masthead and navigation, carefully designed link/focus/hover states, and light/dark themes using prefers-color-scheme. All informational routes receive the same design quality as home/records. A compact explicit theme selector offers System/Light/Dark, progressively enhanced and keyboard accessible; preference may be stored locally only after a visitor explicitly chooses it, solely as localStorage key `se-theme` with value `light` or `dark`; choosing System removes that key and follows the OS. Never store visitor IDs, reading history, queries or clipboard contents. System theme works with CSS alone; storage failures must not break reading or controls. Coder owns concrete tokens and component implementation; architect evaluates compliance and proposes bounded refinements, not a competing design system.
8. Useful dynamics: implement a current-section indicator on long-page TOC links using a lightweight observer (plain anchors remain functional without JS), clear copy success/failure feedback, and restrained short interaction transitions. Respect prefers-reduced-motion: disable non-essential transitions and smooth scrolling. No scroll hijacking, parallax, autoplay, reveal-gated prose, loading theatre, view-transition dependencies, or scroll-driven reading data collection. Mobile navigation must be readable/usable without JS rather than disappear behind a broken menu.
9. Privacy acceptance: no analytics, tracking pixels, fingerprinting, remote font calls, third-party JS/embeds, external preconnect/prefetch, accounts, cookie banners for nonexistent tracking, or required remote API. Site-initiated runtime requests should be same-origin assets only; external publisher/source links load solely when activated by visitors. Clipboard writes occur only on explicit user action. Use a no-referrer meta policy so external source navigation does not unnecessarily disclose the originating archive page; do not modify hosting infrastructure. Update privacy notice only to accurately reflect implemented theme storage and browser-side interactions; retain truthful hosting/network log caveats, never claim anonymity or zero logs. Any changed privacy notice may receive a truthful current modification date determined by tool, not fabricated verification dates for archive records. QA must check actual request/storage behaviour, system/manual themes, reduced motion and no-JS operation.
